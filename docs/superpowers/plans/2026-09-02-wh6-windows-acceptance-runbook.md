# WH6 Windows 期权成交采集器 Staging 验收手册

## 当前可验证范围

- 后端使用本地 SQLite 复现 Supabase Staging 的账户绑定、设备连接码、观察记录和多设备去重。
- 客户端核心以 `match.dat` 为已成交来源，必要时只读关联同名 `order.dat` 补齐方向/开平；选择单个 `Record` 目录时会逐文件回补其下全部历史成交；只接受能验证为期权且具备买卖、开平、交易所、数量、价格和解析器版本的记录。
- `trading_intraday_fills` 是盘中临时事实，不能覆盖 `trading_trade_facts` 的结算事实。

## 当前真实缓存探针（只读）

- 当前 Windows 11 Parallels 虚拟机的 WH6 `Record` 目录已发现 156 个 `match.dat` 文件。
- 使用配套 `order.dat` 只读关联后，解析出 2,353 条可识别的铁矿石期权成交；格式、截断和必需字段异常为 0。
- 当前缓存没有发现可直接信任的宏源账户附属标识，因此账户探针保持“待确认”；首次激活必须由使用者确认脱敏账户，不能按目录名猜测。
- 以上仅是本地回放证据，不是 Supabase Staging 入库，也不是 10 秒实时验收。

## Windows 11 虚拟机步骤

1. 从 `collector/installer` 的构建结果安装 `WH6成交采集器-Setup.exe`，确认没有 Python 依赖，并确认 `%LOCALAPPDATA%\\WH6成交采集器` 已创建。
2. 在 WH6 登录已确认的宏源期货账户；打开采集器，先观察自动候选，再手动选择 `Record` 目录作为对照。
3. 在 Web Staging 管理页“期权成交采集设备”生成一次性连接码；在采集器确认脱敏账户和连接码，检查设备显示为“正常”。Windows 设备令牌应由当前用户 DPAPI 保护后保存。
4. 让首次扫描回补缓存中可识别的铁矿石期权成交；检查本地队列、Staging 标准成交和两张设备/观察记录的数量。
5. 复制安装包到第二台 Windows（或第二个隔离用户），重新连接同一账户；相同成交只能新增观察记录，不得产生第二条标准成交。
6. 在 WH6 切换到其他账户或让当前身份不可确认；确认托盘状态变为“已暂停”，不再上传新来源，原账户队列仍保留。
7. 短暂断开网络，确认新记录进入本地待上传队列；恢复网络后自动重试并清空已确认队列。
8. 在四个参考时段各观察一次状态（09:00–10:15、10:15–11:30、13:30–15:00、21:00–23:00）；节假日不开市不应被当作错误，采集器保持等待。
9. 只通过自然交易产生的一条铁矿石期权成交验证“缓存完整写入后 10 秒内进入 Staging”；不得由程序发单、撤单或修改订单。

## 通过条件

- 账户身份、路径、格式和暂停提示均可理解；完整账户号和 Windows 完整路径不出现在页面/日志。
- 历史回补、重启、文件轮换和两台设备都不丢失或重复标准事实。
- 未知格式、缺少必需字段、冲突记录进入异常，不进入标准成交。
- `trading_trade_facts`、结算单和 Production 没有任何改动。

当前工作区已经完成真实 WH6 缓存的本地只读回放，但没有 Windows 构建工具和 Staging 凭据；因此本手册中的安装包、账户确认、Staging 入库和 10 秒真实成交项仍是 Windows/Staging 验收门，不能用本地 API 测试替代。
