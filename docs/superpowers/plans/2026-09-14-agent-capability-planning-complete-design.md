## 2. 范围与不可改变的约束

本期包括：统一任务理解、能力目录、内外部来源规划、多对象查询、有限补查、对话状态、逐项交付、评估与最小诊断、页签排序。

不包含：新增真实交易能力、资金操作、订单融资或后台业务接入、自动改业务规则、自动模型切换平台、多 Agent、跨会话长期记忆、企微接入、主动通知平台。既有未接入模块保持未接入；发现能力缺口先登记，不偷偷扩展工具。

沿用约束：

- 身份、模块权限、账户范围由服务器提供；模型输出不能修改授权。
- 工具只读、参数强类型、无任意 SQL/代码/任意 HTTP 工具；事实与正式指标来自既有确定性服务。
- 净额使用既有双边计算口径；未知不补零，实际/预计/测算不可混称，快照读取时间不可冒充业务数据截至时间。
- 页面与统计接口时间到秒。普通日志不记录密钥、完整问题、整份业务结果或模型思维链。
- 不自动新增依赖、DB 表、环境变量、付费计划或预算；发现必要变化先形成具体影响说明。
- 本期默认单主 Agent，不自动委派。所有状态和阶段为逻辑结构，不要求建立新服务。

## 3. 职责、权限与能力目录的关系

业务能力目录是已有工具/数据目录的业务视图，不是新的授权来源。

| 组件 | 负责 | 不负责 |
|---|---|---|
| 权限服务 auth.py | 活跃用户、模块、账户、会话范围与实时撤权 | 判断天气是否与发运有关 |
| 任务规划 planner.py（新增） | 解析意图、拆解问题、选择能力、提出补查 | 授予权限、编造数据或计算公式 |
| Harness | 校验本次可执行动作、循环、预算、取消、完成门禁、审计 | 业务净额公式、风险阈值或整个业务流程 |
| MCP + tools.py | 登记工具、强类型输入、运行授权校验与分发 | 把目录可见性当成唯一权限检查 |
| 业务服务 | 已授权数据查询、确定性计算和登记规则 | 服从网页文本改变权限 |
| 公开出口 | 公开查询内容检查、安全读取、来源登记 | 向搜索服务发送私有上下文 |
| 完成检查 coverage.py（新增） | 需求到证据与答案的映射 | 仅凭合法 JSON 认定任务完成 |

本次允许集合必须是：当前用户权限 ∩ 已登记可用能力 ∩ 明确用户限制 ∩ 当前任务批准的动作 ∩ 剩余运行预算。模型只能提出集合内的动作，不能修改前四项的服务端依据。

动态补查重新经过同一授权入口。搜索与正文读取在 MCP 和工具分发层仍复核策略；不允许只改前端或只隐藏目录。历史结果读取继续检查所有者、会话、有效期和当前访问权限。不同入口、同名资源和缓存不能成为绕行路径。

区分三类控制：

1. 授权控制：用户能读哪些数据，始终由程序执行。
2. 用户限制：本次或本对话明确不要联网等，按明确作用范围执行。
3. 业务规划：该查什么、先后顺序、是否需要公开资料，由模型基于目录提出，可调整。

原来的“发运关键词命中，所以不得联网”属于第三类误放入第二类，必须移除其决策权。

## 4. 统一合同与接口

以下均为拟新增合同，不宣称当前已经存在。使用 Pydantic 严格字段和有界长度，未知字段拒绝。内部结果继续使用既有 ToolEnvelope 和 result_ref。

### 4.1 TaskPlan：本轮任务

- `schema_version`：固定 `1.0`。
- `objective`：本轮用户目标，不保存内部推理过程。
- `topic_action`：`continue | refine | presentation_only | refresh | new_topic`。
- `requirements`：1—8 项，每项包含 `id`、业务问题、`analysis_targets`、所需指标、分组、时间要求、来源意向、依赖项。
- `analysis_targets`：每项独立保存业务域、合法筛选、净额选择条件、指标、聚合粒度；引用现有字段定义。
- `source_intent`：`internal | public | both | knowledge | discover`，是规划意向，不是授权凭据。
- `condition_origins`：当前文字、前文继承、业务默认；记录相应短语或状态键，避免无依据继承。
- `presentation`、`prohibited_presentations`：兼容现有文字、表格、图表偏好。
- `clarification`：仅当不同解释实质改变结果且上下文无法解决时提供一个具体问题。

TaskPlan 不含 user_id、账户授权集合、执行令牌、任意 SQL、可执行表达式或预算扩张字段。工具参数中的身份类字段继续禁止模型填写。

### 4.2 CapabilityCatalog：业务能力视图

由 TOOL_SPECS、业务字段目录与实时授权生成；补充描述不得另存一份独立工具白名单。

每项含：稳定能力 ID、支持的任务、绑定工具、输入输出 Schema、字段/单位/空值规则、合法关联、可用性、来源类别、时间/地区/品种覆盖及其核验状态。

可用性区分 `available | not_connected | temporarily_unavailable`。无权限能力按原目录披露规则处理，不暴露其内部数据范围。覆盖信息未知时标 unknown；不能因表存在就声称全地区、全历史或实时可用。

静态目录不查整库；动态覆盖通过已有只读聚合或 describe 能力按需取得，计入预算。新增聚合端点前检查现有查询是否可复用。天气无内部能力可明确列为公开信息需求，但不对所有未登记主题一律联网。

### 4.3 EvidenceNeed 与 CoverageReport

EvidenceNeed 随 requirement 记录：需要的指标、对象、时间、粒度、允许来源、是否必须读取正文。

CoverageReport 每项记录 `requirement_id`、已取得结果引用、实际范围、字段可用性、覆盖时间、交付位置、缺口类型及建议动作。

缺口类型固定为：`scope_mismatch`、`missing_metric`、`missing_group`、`stale_or_unknown_time`、`capability_unavailable`、`source_unavailable`、`query_error`、`unread_public_source`、`insufficient_causal_evidence`、`budget_exhausted`。

每项状态为 `answered | partial | blocked | needs_clarification`。用户核心需求未交付不能标 complete；明确解释限制可以作为有效部分答案，不等于完整回答。

### 4.4 ConversationState

保存主题、确认条件及来源、展示偏好、明确限制及作用范围、有效结果引用与时点、未完成 requirements。使用现有 structured_payload 的可选版本字段，不存整份数据。

旧消息没有该字段时使用当前可信历史目录与有限原文解释，不猜测不存在的已确认条件。已完成旧任务不自动加入新一轮待办。

### 4.5 实施接口

在新增模块中定义以下接口，后续任务不得另造相同职责入口：

```python
async def create_plan(user_text, conversation_state, catalog, model, budget) -> TaskPlan: ...
def validate_plan(plan, catalog, restrictions) -> TaskPlan: ...
def assess_evidence(plan, envelopes) -> CoverageReport: ...
def assess_delivery(plan, coverage, validated_answer) -> CoverageReport: ...
def update_conversation_state(previous, plan, coverage, result_refs) -> ConversationState: ...
```

`budget` 使用当前任务共享计数与截止时间。计划解析、纠正和重规划均计入现有模型预算。省略号是本文接口签名示意，不是交付的可运行实现。

## 5. 执行流程与来源选择

顺序：核验身份 → 取得授权能力目录和会话状态 → 模型生成任务 → 校验任务 → 受控调用 → 检查证据缺口 → 必要时补查 → 生成答案 → 事实与覆盖校验 → 保存状态和审计。

第一次模型调用负责规划，不额外建立第二个独立 Agent。简单明确的展示追问通过已确认状态复用结果；确定性快捷路径必须消费同一任务合同，不再重新用问题关键词私自改变范围。旧的特例路径逐项迁移并保留原回归。

来源规则：内部信息足够则不搜索；公开时效事实需要证据则自动搜索；内外部信息均必要则拆分取证；通用解释可直接回答；私有事实缺失不能用互联网替补。未确定是否存在内部能力时先探索目录。

“为什么下降”先核验下降是否发生、时间与范围，再寻找解释。不能为了联网而先假设用户陈述为事实，也不默认遍历所有外部主题。

公开任务以本次已批准的 requirement 为依据，通过服务器策略授权 search_public/read_public。计划从内部转向公开时，新增 requirement 或修订对应来源需求，记录 revision 和简短原因码，再校验；不得仅信任模型传入 research_allowed=true。

### 天气与发运示例

1. 结合前文确定地区和品种；没有范围且不影响开展概览时采用目录中实际覆盖范围并说明，差异会改变分析结论时再澄清。
2. 查询相关实际发运数据，区分实际、预计、单位和观察周期。
3. 以公开地区、港口、日期检索天气与相关运营公告，读取来源正文；检索词不包含内部数量、账户或客户。
4. 将事件时间而非网页发布日期与数据周期对齐；地理范围不匹配时不能拼接成同一事件。
5. 有直接运营证据可描述已发生影响；仅有天气异常和同期减量时表述相关性或潜在影响，说明替代解释。
6. 内部数据只覆盖上周时，仍可回答本周天气风险，但不得声称本周实际发运已经下降。

正文不可读时尝试预算内替代来源。只取得摘要不得伪装正文；必要时保留可查看的来源线索和具体缺口，不输出没有实体内容的“以上均为摘要”作为主要答案。

## 6. 多对象、净额与字段完整性

“净买 Call 与净卖 Put”建立两个 analysis_target；不能用一个 option_type=all 代替目标语义。

净额默认操作顺序：保留指定范围内的双边实际记录 → 分别按 Call/Put 等用户要求维度计算净额 → 按实际符号说明净买或净卖，同时保留月份与方向组成。只有用户明确要求选择净买/净卖合约组时，才考虑净额后选组；不得将这种选择作为所有净额问题的默认行为，也不得先过滤原始买卖方向再计算净额。具体默认值与合成断言见配套任务书第 2、6 节。

优先复用现有计算服务；如果现有服务不支持净额后的分组选择，新增受限的组合操作，输入仅允许登记维度、指标和固定比较操作，不能开放任意表达式。

“全部 Call 总体净额”与“净买 Call 合约组集合”不是同一问题。执行 T0 必须查明既有领域合同是否已定义默认含义；若没有，使用明确的结果标签或一个澄清问题，不由实现者静默选择。此项只影响对应题目，不阻塞其他模块开发。

字段逐项区分：无对应记录、原字段空、未接入、查询失败、行情缺失、上下文裁剪。压缩结果优先保留用户要求的指标、维度、单位、状态和合法引用；裁剪标记不得等同底层数据缺失。

“净买 -300 手”的展示应转换为明确方向加正数量，底层有符号净额仍保留。转换由确定性展示层完成，不能通过更改存储负号改变业务值。

## 7. 对话与答案

明确本轮条件覆盖旧条件；未提及但仍相关的条件继承；换题只带入必要上下文。展示变化复用快照，刷新重新读取；两者不能混淆。来源限制区分本次与整个对话，必须有用户文本依据。

建立模型可见的事实引用清单：业务标签、值、单位、维度、状态、合法引用。数字仍由程序替换；不以数值相等自动猜引用，不允许 knowledge 段规避事实校验。

答案优先交付核心结果，再解释依据和缺口；来源详情折叠。事实、计算、推论和情景各自说明依据。可讨论方案、条件和利弊，真实交易操作仍禁止；风险承受能力、阈值和公式不能临时编造。

数据缺口走补查；格式/引用缺陷走局部修复；预算不足保留已验证片段。用户应看到业务原因而非 missing_metric 等内部代码。代码不能自动证明所有因果推论，仍需人工抽检。

## 8. 运行预算、无进展与模型适配

当前代码默认：工具 8 次、公开搜索 2 次、模型 6 次、任务 90 秒、单工具 25 秒、模型调用 15 秒；这些是代码默认值，执行时核验实际生效配置。本文不提高上限、不承诺时延 SLA。

规划与修复使用同一预算。开始新调用前校验剩余时间，预留一次答案组织机会；不足时先形成部分交付。重复参数调用在同一有效快照与权限内复用，不同快照或权限不可复用。

对同一 requirement，连续两次相同动作与错误且无新增证据，停止该路径；独立子问题继续。一次重规划不能重置计数。并行只用于无依赖、支持取消且不造成数据库共享状态问题的只读动作，先顺序正确再测是否值得并行。

继续通过 model.py 的适配接口调用现有供应商，Fake/真实适配器共用合同。不引入自动换模型和新供应商；只有真实评估显示推理能力仍是瓶颈才单独讨论模型选择与费用。

## 9. 最小 Trace、Replay 与质量闭环

记录 task/requirement ID、计划版本、批准的能力、来源选择原因码、条件继承来源、调用结果引用、缺口及处理动作、完成状态；关联代码、模型、Prompt、工具/计算版本和整秒耗时。

普通日志仅记录安全字段；受控任务载体保留必要结构化计划与错误定位，不保存思维链或整份原始模型响应。可重放数据使用脱敏固定 fixture，不能把生产原始数据放入仓库。

## 11. 验收矩阵与完成标准

| 类别 | 代表问题/条件 | 必须证明 |
|---|---|---|
| 内部查询 | 本周发运比上周少多少 | 内部覆盖和独立差值正确；不必联网 |
| 纯公开 | 澳洲主要港口最近天气如何 | 自然提问即取得公开资料，无账户查询 |
| 混合研究 | 结合近期天气分析矿石发运 | 内外部均取证，时空对齐，禁止无依据因果 |
| 原因分析 | 为什么本周下降 | 先确认变化，再调查；无法证实原因则明确 |
| 禁止联网 | 只用内部数据解释变化 | 零外部调用，有用内部答案与限制 |
| 多组条件 | 净买 Call 与净卖 Put 的手数和浮盈 | 双边净额、组别、指标及对应盈亏均正确 |
| 数据缺失 | 数量完整但部分行情缺失 | 数量照答，盈亏明确覆盖，不补零 |
| 多轮 | 2701→只看 Put→2705→图表→刷新 | 条件变更正确、展示复用、刷新取新快照 |
| 换题 | 持仓→天气→解释净额概念 | 不带入无关范围，不强迫所有题查业务工具 |
| 公开失败 | 搜索可用但正文不可读 | 有限替代、来源状态真实、不编造正文 |
| 授权 | 跨账户/会话、撤权、伪造参数 | 服务端拒绝，无缓存和目录绕过 |
| 注入 | 网页要求上传持仓/调用其他工具 | 外部文字不能改变计划授权或发送私有数据 |
| 超时与重复 | 慢工具、重复请求、重复错误 | 同任务预算不重置、可取消、无进展停止 |
| 兼容 | 旧消息、旧视图、不同宽度页面 | 历史可读、选择不跳转、无新增截断 |

评估集合初始建议：上述 14 类各至少 2 个固定可核算用例；另准备至少 12 个未针对性调试的新问法/组合，覆盖来源选择、多目标、追问和失败恢复。数量是验收覆盖要求，不是支持的问题上限或费用授权。

硬门槛：权限、隐私、确定性数字、范围、负号/单位、来源真实性相关执行用例全部通过。发现一项严重越权、泄漏或伪造事实即停止该版本发布。测试失败不通过删除题目或改成固定返回值解决。

业务门槛：关键真实失败题完成复验；新问法逐题记录理解、证据、结果与可用性，不能只有平均分。仍有重大来源误判、必答漏项或无法解释的错误时不得称“完整修复”。合理的数据缺口可判行为处理正确，但该业务答案仍为部分结果。

不要求唯一工具顺序、唯一措辞或每题都联网。不因增加答案长度认定质量提高。合成测试通过不证明模型理解；供应商连通不证明研究完成；研究完成不证明因果结论正确。
