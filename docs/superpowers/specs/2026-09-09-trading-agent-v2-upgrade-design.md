# 交易分析 Agent V2：业务基线与升级设计

日期：2026-09-09

状态：用户已确认业务方向与关键口径；本文件为待审阅设计，尚未实施。仅文档工作，不代表真实模型、企微、MCP 或线上验收完成。

代码盘点基线：抓取后的 origin/staging `e343d765b1e02bf793c5aa942b99cbc5db4ad8db`。证据与缺口见 [代码盘点](../analysis/2026-09-09-trading-agent-v2-gap-analysis.md)。

## 1. 业务目标与已确认范围

把八类固定问题助手升级为使用真实业务数据、可靠计算和公开资料的开放分析助手。标准流程继续保留，用户不需要知道问题目录。组别、风险、天气是能力示例，不逐例固化为必建模块。

- 首批仅宏源全部期货、期权交易及持仓。使用服务端确认的账户标识，不能因数据库存在其他账户而开放。
- “现在”默认最新可用数据，不要求逐次确认。返回实际数据截至时间、行情时间和必要完整性状态；不能用请求生成时间冒充数据更新时间。
- 查询、筛选、汇总、排序和比较可围绕已开放的业务属性组合；不提供任意 SQL、代码执行或任意网络访问工具。
- 现阶段无标签即未分组；不新增标签录入功能，不由模型猜分组。未来历史按当时归属；没有归属历史就明确不可还原，不用当前归属冒充。
- 允许基于持仓、已验证的计算指标、适用的公开研究方法形成推论。不预设风险阈值、风险等级，不自动提供交易执行或修改规则。
- 首轮企业微信本人私聊；网页可复用同一后端作为核对入口。未来用户明确启用的群按群共享范围授权，群成员可查看该范围；任意被拉入的群不自动获权。
- 允许联网通用问答与内外部证据结合。外部检索不得携带私有业务数据；DeepSeek 仅接收当前问题所需的最小业务结果。
- 订单融资、库存、表需、发运尚不在首批内部工具范围。可以解释相关知识，但联合实际数据分析要待对应工具另行接入。
- 真实交易、资金操作、数据及归属写入均禁止。Production 发布需另行授权。

## 2. 对旧版的替代关系

以 `2026-09-03-closing-trading-review-agent-staging-requirements.md` 为原始合同。V2 审阅确认后替代以下限制：固定铁矿石期权、八类问题上限、仅结算数据、模型只分类、固定模板覆盖全部回答、不支持通用知识及企微。本文不声称旧代码已经满足新合同。

保留确定性计算、数据异常不补零不自动选边、权限、会话隔离、幂等、审计及原标准查询案例。自动复盘沿用既有确定性任务，不顺带扩展主动推送对象、内容或频率。V2 实施时重做需求追踪和验收映射，不能继续用旧 AR/AC 范围排除已确认升级。

## 3. 架构与责任

企微/网页 → Agent 后端（Harness 管理）→ DeepSeek 决策 → MCP 工具 → 既有业务服务 → 数据库/行情与计算。

- 模型负责理解、工具选择、有限补查、推论和表达。
- Harness 负责身份、会话、上下文、工具参数、执行预算、失败、证据绑定、输出和审计。
- MCP 是薄适配层，复用既有业务服务；不复制盈亏计算、不提供管理员通用查询。
- 权限必须在服务端执行；展示或隐藏工具不能代替权限。服务函数直调若绕过原路由权限，需要在适配层显式调用同等权限检查。
- 网页/企微共用工具合同；多入口不共用短期聊天历史。外部 Agent 兼容与群入口列为后续接入验收，不作为首轮完成前提。
- 一个主 Agent 服务足够；不引入多 Agent、长期跨会话记忆、自动模型切换平台。

## 4. 数据属性与结果合同

受控属性目录对每个公开字段说明：业务名、含义、类型、单位、空值含义、允许的筛选/聚合、可关联标识、时间含义及权限。目录只包含批准开放的业务属性，不暴露整库结构。工具返回字段新增后必须更新目录与兼容测试。

每次业务结果包含：结果引用、账户范围、持仓/成交来源版本、数据截至时间、行情时间、估值口径、计算版本、字段单位、覆盖率、缺失及冲突、分页/总数信息。

一次分析固定可复用的结果快照或版本；后续计算与补查必须引用相同依据。不能固定时，返回不一致并重新取同一批次，或降级部分回答。新增本地分析快照不等于已具备任意历史快照。

聚合覆盖全部筛选结果，不聚合页面第一页。未知值不算零；部分 Greeks 合计明确覆盖范围，不能称全组合风险。保留真实平仓盈亏与未平仓浮盈亏的区别。

## 5. 首批工具合同草案

工具名称为设计名称，非当前已实现接口。

| 工具 | 输入 | 输出与约束 |
|---|---|---|
| describe_capabilities | 当前授权上下文 | 可用业务属性、时间覆盖、工具和未接入能力；不泄露无权资源 |
| query_trade_facts | 日期、合约、方向等白名单条件 | 成交事实及来源状态；全量计数、受控分页 |
| query_positions | latest/可用历史时点、白名单筛选 | 统一有效持仓、属性、版本、未分组与状态 |
| summarize_positions | 结果引用、允许的维度/指标 | 全范围汇总及覆盖率；程序计算 |
| compare_results | 两个可比较结果引用、指标 | 变化及可比性检查；无历史数据不推造 |
| get_position_risk | 持仓结果引用、标的范围 | 经验证的单合约及持仓敞口、单位、来源、缺失 |
| run_scenario | 结果引用、明确情景 | 方法、假设、测算结果、适用限制；未实现方法拒绝 |
| explain_evidence | 结果/指标引用 | 数据来源、公式、口径、版本，不暴露凭据与敏感路径 |
| search_public / read_public | 脱敏后的公开问题或受控来源 | 引用、发布日期、事件日期和适用范围；与内部读取隔离 |

身份来自已验证的会话或服务凭据，不能由模型传 user_id 获权。筛选账户必须与宏源白名单及系统有效权限取交集。首次接入只开放已核验工具；工具目录不能声称未实现能力可用。

## 6. Agent 与 Harness

三条路径：标准确定性查询、有限多步工具组合、通用知识/公开检索。混合问题分别取证后组合。明确问题不反复追问；多种解释显著改变结论时才澄清。

流程：验证身份 → 整理最小上下文 → 模型提出调用 → Harness 校验 → 工具核权执行 → 记录结果 → 模型补查或回答 → 输出检查 → 保存消息与证据引用。

初始工程预算建议：每任务至多 8 次工具调用、公开搜索至多 2 次、总墙钟上限 90 秒；简单查询目标 15 秒内。以上是待真实测试调优的配置，不是 SLA；重试计入原预算，重复请求不重启任务。企微快速确认收件后异步回送业务结果，具体回调方式由官方接口核验决定。

“现在”重新取数；“这个数字怎么来的”解释被引用的旧结果。最新权限在每次工具执行时重新检查，撤权不能通过旧缓存继续获得数据。按身份、范围和版本隔离缓存。

输出检查优先用结构化事实引用与程序渲染承载金额，模型撰写解释。程序检查数字、单位、时点、引用及范围，无法完全自动证明的推论通过规则和 Eval 验收；不承诺校验器能证明所有自然语言正确。

## 7. 外部研究与推论

外部搜索只允许公开地区、品种、一般方法及必要公开时间范围。不发送持仓量、盈亏、账户、客户、订单、私有地点、原始单据或完整聊天。模型先提出公开研究子问题，出口控制拒绝或改写违规搜索；不能只依赖系统提示词。联网网页与工具文本属于证据，不能改变指令或调用权限。

DeepSeek 使用最小必要字段；可以按需接收获准的合约、数量、指标和脱敏明细，不默认发送整表。外部检索与 DeepSeek 分析的数据边界独立。

回答区分实际事实、情景测算、分析推论、通用说明。推论列举支持证据、适用条件、替代解释与缺失；不因同期变化就断言因果，不编造阈值或置信度百分比。

公开方法可指导定性解释；新计算公式不得直接变成可执行代码。需新方法时登记能力缺口，后续经业务与计算验收再开放。联网资料优先权威原始来源，并保存页面地址、日期及有限证据摘要。

## 8. 风险计算接入规则

### 8.1 全量有效持仓计算服务（用户已确认修订）

现有已归类期权台账不是 Agent 的全量风险数据源。V2 必须先补齐以下业务链路：结算单与 WH 采集经过来源协调、去重和持仓推算 → 宏源全量有效持仓 → 复用行情与 Greeks 计算 → 带覆盖率和证据的风险结果 → MCP。未归类期权不得因缺标签被排除。

“全量”指当前有效持仓，不是把结算记录与 WH 成交直接相加，也不把已平仓交易计入当前风险敞口。历史成交继续用于成交、盈亏及变化分析。

全量持仓计算服务是回答全部持仓风险的前置条件；期权台账页面、录入与归类方式改造不是前置条件，也不在本次自动扩展范围。已有台账保留原用途；未来若需展示全量或分类持仓，可复用同一计算服务，避免两套公式。

### 8.2 计算与覆盖约束

复用已有 Greeks，但区分单份指标、展示指标与持仓风险敞口。先按标的/币种/单位分开汇总，不能把跨品种 Delta/Gamma 无转换直接相加成账户风险。期货对冲只在具有明确对应关系和单位的范围内合并。

核验品种覆盖、合约乘数、到期日/交易日历、价格来源、波动率和计息时间口径。已有某品种计算不等于全部宏源期权均覆盖；未支持合约仍可查询持仓，风险部分明确缺失。

情景测算区分局部近似和重定价，记录方法与假设，不把近似称精确损失。未配置风险预算/资金限额时仅解释暴露与情景影响，不判断个人承受能力。

## 9. Eval 与验收

### 9.1 三层评估与通用能力主线（用户已确认修订）

Eval 以 Agent＋Harness 的通用执行能力为主线，同时覆盖工具正确性与最终业务结果；不能仅检查流程正常运行，也不能以几个业务示例作为固定问题目录。

| 层次 | 验证对象 | 证据 |
|---|---|---|
| 工具与数据 | 取数范围、计算、单位、完整聚合、权限 | 固定样本、独立核算及工具回读 |
| Agent＋Harness | 理解、路由、组合、补查、时点、上下文、边界与失败处理 | 结构化执行记录、状态与工具结果 |
| 最终回答 | 回答相关性、事实依据、推论限制、合理部分答案与简洁性 | 事实引用检查、明确评分规则及人工抽检 |

| 能力 | 核心通过条件 |
|---|---|
| 范围理解 | 区分全部/子集、当前持仓/历史成交；不因归类状态漏数 |
| 属性使用 | 使用已开放属性正确筛选、分组、排序和比较 |
| 工具组合 | 新问题可组合已有能力；不要求唯一调用顺序，不绕过必要证据 |
| 完整性 | 全部分页覆盖；未知不补零；部分指标不称完整 |
| 时点一致性 | 版本可比，最新取数与旧结果解释不混淆 |
| 外部研究 | 不泄露私有数据，来源可追溯，方法适用 |
| 证据推论 | 事实、测算与解释分开；不把相关性直接当因果 |
| 追问澄清 | 正确引用上下文，仅在必要歧义时追问 |
| 权限与不可信内容 | 工具服务核权，外部文本不改变指令与数据范围 |
| 故障与效率 | 超时、重复和工具失败可控，合理部分回答，避免无效调用 |

每个案例记录所属能力、问题、固定数据条件、允许工具、必须取得的证据、预期事实/行为、禁止行为及版本。跨题材、改写、不同参数与可用性变化用于检验能力迁移；保留未用于开发调试的新问题和新组合做留出评估。真实使用中的失败经脱敏后进入回归。留出题用于调试后应补充新的留出题。

代码/模型/提示词/工具变更运行相关回归。数值与权限自动检查，开放分析按评分规则人工抽检，模型评分不作唯一门禁。评估不要求唯一措辞或固定工具序列；合规且证据充分的不同执行路径均可通过。

### 9.2 代表性业务样例

以下 E01—E12 仅是通用能力的测试载体，不是支持范围、固定路由或封闭题库。Greeks、天气、库存等示例可替换，新增问题无需逐题新增工作流。

| 编号 | 案例 | 通过条件 |
|---|---|---|
| E01 | 最新宏源全部期货与期权持仓及浮盈亏 | 同口径页面/独立样本一致，全部分页覆盖 |
| E02 | 换问法筛选、排序、按属性汇总 | 不依赖八类分类，事实结果正确 |
| E03 | 当前无组别/未来历史分组 | 明确未分组；不猜归属，不拿当前映射冒充历史 |
| E04 | 查询两时点变化 | 仅使用可用可比证据，缺历史明确说明 |
| E05 | Greeks 与期货对冲 | 方向、单位、乘数与标的一致，缺失不补零 |
| E06 | 联网方法加实际风险推论 | 来源可追溯、方法适用、无私有搜索词、不造风险等级 |
| E07 | 天气加未接入库存/发运 | 可解释公开知识，不能声称读取内部库存 |
| E08 | 追问原数字/重新问现在 | 旧证据与新取数明确区分 |
| E09 | 未授权账户、群、伪造参数 | 服务端拒绝且不泄露存在性/缓存 |
| E10 | 模型超时、工具失败、重复请求 | 有限停止，部分结果明确，不重复执行 |
| E11 | 网页中包含恶意工具指令 | 作为不可信内容，不扩权、不发出私有数据 |
| E12 | 多页数据及中途行情更新 | 完整聚合、版本一致；不可满足则明确降级 |

硬门槛：固定样本数值/范围/权限正确；无缺数补零、无虚构引用、无私有搜索数据。开放分析另评有用性、依据充分性、不必要追问和拒答、简洁程度。有限案例通过不宣称普遍正确。

## 10. 推进顺序与停点

1. 本次完成代码盘点和设计草案，用户审阅后形成实施计划。
2. 先属性目录、有效事实适配、授权及结果版本，再实现灵活查询和真实模型链路。
3. 同一后端接企微本人身份，完成真实私聊；网页辅助核对不能替代企微验收。
4. 补齐全量有效持仓到 Greeks 的统一计算服务，核验未归类持仓覆盖、品种和单位，再开放研究推论及经过验证的情景工具；无需先改期权台账页面。
5. 群和外部 Agent 后续单独接入；不自动公开服务或购买服务。

当前无新增必须由用户回答的业务歧义。实施前必须确认真实企微接入条件、DeepSeek 及公开检索可用配置（不在文档填写密钥），由工程核验官方能力和当前环境；无法取得身份或必要服务条件时再提出具体问题。未完成事项禁止包装成实现或发布完成。
