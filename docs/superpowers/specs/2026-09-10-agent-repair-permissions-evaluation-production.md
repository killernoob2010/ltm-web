# 智能贸易助手：整体修复、模块权限与运行质量后台实施规格

版本：1.0｜日期：2026-09-10｜状态：业务需求汇总及供 Luna Max 实施的设计基线；尚未实施、尚未验收。

## 0. 如何使用本文

本文汇总用户在当前对话中确认的需求，供主 Agent 审核及 Luna Max 执行。本文交付不等于已启动子 Agent，不代表代码已修复或正式版已更新。

本文优先覆盖旧方案中与以下事项冲突的规则：366 天/3 年份限制、固定词语联网门禁、固定主题拒答、评估仅限定义检查、Agent 必须经过免费 Staging 的发布路径。其他既有正确业务语义继续保留。

需求来源分为：

- **已确认要求**：多年查询、正确识别公开研究、六模块权限、后台信息禁止经 Agent 获取、可视化运行与评估后台、正式版部署和管理员验收。
- **实施默认设计**：本文明确标为默认的接口形态、页面分组、异步评估方式等，是为便于执行给出的方案，不冒充用户逐项指定。执行者可适配既有框架，但不得改变业务结果、授权边界或验收标准。
- **暂不实施**：未接入业务模块的新工具、第三方评估平台接入、自动模型评审付费任务等，见第 2 节。

## 2. 本期范围与非目标

本期实施：

1. 修复已有交易与数据可视化 Agent 能力的多年查询、展示、联网和权限问题。
2. 建立六模块接入/授权注册规则，不把尚未接入的模块假装成可调用。
3. 后台管理新增“Agent 运行与质量”入口，提供运行概况、质量与反馈、调用明细、版本验收。
4. 执行式 Evaluation：确定性检查、受控真实模型用例执行、人工复核、固定数据版本比较。
5. 按已授权路径正式发布，并核对实际业务结果。

本期不实施：

- 不新增贸易台账、信息预警、订单融资等目前未登记的 Agent 数据适配器；后续接入必须单独确认字段、工具和验收。六模块权限框架不等于六模块全部接入。
- 不修改订单融资、台账或预警业务本身；其独立测试问题与 Agent 验收分开报告。
- 不把 Agent 做成通用后台助手；不注册用户、权限配置、日志、系统配置或评估管理 MCP 工具。
- 不重构全站权限模型，不凭一级菜单可见性扩张子资源权限。
- 不开放自由 SQL、代码执行、任意地址抓取、交易操作或资金操作。
- 不重新定义库存、到港、表需、浮盈亏等事实口径；不增加未经确认的因果或跨口径同比算法。
- 不购买/充值/升配，不自动上传问答至第三方评估平台，不建设自动自我修改或自动优化发布系统。
- 第一版不启用后台批量 LLM-as-judge；允许扩展评分来源字段，但不得出现空壳按钮或假评分。受控真实模型问答验收与模型评分是两回事。

## 4. 业务模块与服务端权限

### 4.1 六模块注册表

| 业务模块 | 已存在的资源/权限线索 | 本期 Agent 接入规则 |
|---|---|---|
| 贸易台账管理 | `spot_ledger.records` → `spot_ledger` 等 | 仅登记模块归属；未接入适配器不可查询 |
| 交易管理 | `trading.facts` → `trading_positions`，及 overview/options/junneng 等 | 只开放实际登记工具及其必要资源；账户隔离继续有效 |
| 信息预警管理 | `alert.*`、`INFO_WARNING_MODULES` | 仅登记模块归属；不得自动开放预警设置或历史 |
| 数据可视化管理 | `data_visualization.*` 分别映射 chart/data/integration/report | 按实际数据服务及所需子资源鉴权，不能拥有任意子页就读全部 |
| 订单融资管理 | records → progress，capital → capital | 未接入时说明未接入；不是永久禁止的模块 |
| 后台管理 | users/permissions/operation_logs/monitoring，以及本期评估后台 | 业务 Agent 对任何用户硬拒绝，包括管理员 |

该表是实现入口，不是新增授权清单。实际工具需登记：业务模块、接入状态、必需资源集合、数据范围要求、允许字段、只读属性及策略版本。未知模块、未知工具、未映射资源默认拒绝。多资源工具必须全部满足，不以任一权限代替全部权限。

允许业务数据读取的条件：有效用户及会话 + Agent 入口权限 + 已登记/已接入工具 + 非后台禁止资源 + 所有必需资源查看权限 + 既有账户/行范围。

服务端内部可读最少身份信息完成鉴权，但只向模型提供本次必要的可用工具和能力，不提供用户列表、权限表、他人授权状态、后台配置等原始数据。

### 4.2 四层防护

1. Harness/能力目录：过滤未接入、无权限和禁止工具。不把隐藏工具的 schema 或敏感动态筛选项发给模型。
2. MCP 及数据服务：每次调用重新检查，不信任模型传入 user_id、模块授权、结果归属或任意 resource；直接调用同样受控。
3. 快照及派生结果：记录来源资源和父结果；分页、图表、证据、组合结果要求全部来源的当前权限。缺失来源权限元数据的旧结果应拒绝复用或引导重新查询，不默认为公开。
4. 历史和输出：新一轮输入不能把已撤权的历史数据文本再发给模型；历史答案/明细接口也必须核验来源。已显示或用户自行保存的内容无法追溯收回，不能宣称能收回。

数据库访问前鉴权；权限可能在调用过程中改变时，交付敏感结果前复核。缓存按用户/会话/权限有效性隔离，不依赖长时间过期策略代替撤权生效。错误消息不泄露无权数据是否存在、行数、筛选值。

### 4.3 混合问题与未接入模块

- 两个模块均有权限：分别查询，明确数据来源和可比较口径。
- 只有一个模块有权限：交付允许部分；受限部分说明无法访问，整体需求覆盖标部分完成。
- 尚未接入：说明当前未接入，不猜测内部数据，不用公开搜索替代内部事实。
- 不再按“订单融资”关键词一概拒绝所有通用知识。知识/公开研究不构成内部模块数据授权；能否回答仍遵守助手职责及用户意图。后台具体内容始终禁止，不能伪装成“知识”输出。
- 未经登记关系不得因同时有两模块权限就自由 JOIN 数据。

## 5. 多年查询与展示

### 5.1 查询契约

- 移除新数据集、旧期现接口的固定 366 天限制及三年份数量限制；保留合法日期、顺序、已登记字段和既有年份有效域。
- years 去重、排序用于确定性处理；不要按任意前三年截断。最新数据、连续期间、季节对比仍明确区分。
- 空年份、缺周、闰日保留真实缺失；不能把导入时间当观察日期，不能把空值替换为零。
- 支持五年、十年等查询是对已有数据覆盖而言，不承诺数据库具有这些年份。
- 更新工具参数说明、目录限制信息、提示词、旧测试、旧计划中的冲突条款；保留旧调用参数兼容性。

### 5.2 有界读取

默认设计：保留单批 20,000 行和单快照 10MiB 等现有保护，核对实际常量后复用；通过服务端分页/确定性期间分批解决大范围，不由模型拼接任意 SQL。

- 同一逻辑查询关联 query_group 标识、规范化筛选、源版本、请求期间、批次范围、返回数量、完成状态与缺失原因。
- 游标由服务端生成并绑定查询、用户和数据源版本；不可把另一用户游标或不同筛选混用。日期分区边界明确，不因含首含尾造成重叠。
- 稳定排序包含唯一业务键；同一天超过单批容量时必须能继续分页，不能反复按年份拆分至死循环。
- 源数据有现成版本时绑定该版本；无版本时使用可验证的一致读取方案或检测变化后停止并要求重查，不混合新旧批次后标完整。
- 小范围可在一次任务内完成；超任务预算返回安全的继续读取入口，承接同一查询和权限。不能自动无限运行或增加模型/工具预算。
- 每批内数值汇总与跨批合并由确定性服务执行；只有无遗漏、无重复、单位和口径一致时，才能称全期间汇总。不能用预览值或平均数的简单平均代替完整计算。
- 分批派生结果复用现有父结果权限和祖先数量/深度保护；不得关闭这些保护。无法在现有结果协议中有界表示时，向主 Agent 提交局部设计调整，不私自扩成数据仓库。

### 5.3 图表和表格

- 取消单条曲线 366 点对连续多年展示的独立限制，使用已有总点数/响应字节约束管理容量。
- 季节图例必须保持年份，品种对比保持品种与年份；连续时间轴、业务周轴和月日轴明确区分。未指定且会实质改变比较口径时询问或明确采用已有页面口径。
- 默认保留每页 6 个分面、18 条曲线、8192 总点、2MiB 响应等容量保护；超限采用确定性分页或完整表格降级，明确本页覆盖，不能静默丢年份。
- 不擅自将日度转成月度、不抽样冒充全量。负值零轴、缺失断线、提示中的真实观察日继续有效。
- 相关视图分页、总量及继续状态必须与数据结果一致；图谱翻页不触发新取数。

## 6. 问题理解与公开研究

### 6.1 结构化计划

修复固定词匹配决定全部搜索能力的问题。默认采用一次受限模型语义规划，在服务端校验后执行；规划调用计入现有模型预算和任务总时限，不新增无限重试。

计划至少表示：

| 字段 | 含义 |
|---|---|
| intent/subquestions | 当前问题及必要上下文中的子问题，不含推理过程 |
| module/source_kind | 每个子问题所属模块；内部、公开、通用解释或未支持 |
| requested_period/freshness | 历史期间或当前公开信息时效要求 |
| research_requirement | 必须、可选、禁止或存在冲突 |
| required_resources | 从服务端注册表解析，不能信任模型直接授权 |
| clarification | 仅真实歧义需要的业务澄清 |
| policy_version | 实际执行的策略版本 |

模型只能提出计划，不能授予权限。工具可见性、后台禁用、用户禁止联网、输入隐私、工具和金额预算均由程序执行。纯内部问题不应仅因需要“解释原因”就自动发送私有事实到外部。

禁止联网必须处理否定作用域，例如“不要联网”不应因为包含“联网”而被自身识别成矛盾；“不要联网，但请搜索最新政策”才存在两个冲突指令。规划失败时明确失败/澄清，不能默默把必须外部的请求改成内部完整回答。

多轮上下文只使用当前仍有权限的数据。上一轮允许搜索不延续为永久允许；“再结合最新供需”应承接业务主题。网页文本不参与授予权限或修改用户请求。

### 6.2 搜索执行和答案完整性

- 使用已有公开搜索及来源阅读链路，不更换供应商或新增付费服务。
- 搜索词仅包含必要公开主题，不包含内部金额、账户、订单、客户编码或结果数据。规划输出不能未经隐私校验直接用作搜索词。
- 搜索与阅读的允许状态必须在服务端当前任务计划中保存；缺失、过期、所有者不一致或写入失败不得绕过限制。
- 查到链接不等于读过正文；优先原发布机构，保留可核对 URL、日期/未知日期、摘录及其支持的结论。禁止编造引用。
- 外部资料不能支持内部数量；内部结果不能证明外部事件；相关性不表述为已证明的原因。
- 用户必须外部的子问题未取得有效资料时，内部部分仍可交付，但整体 coverage 为部分完成，解释缺失原因。模型不能用知识段落绕过引用要求。
- 服务缺配置、403、超时、正文不可读均有可区别的运行记录。记录错误类别，不记录密钥、完整私有请求或敏感异常堆栈。
- 继承当前任务上限（编写时为工具 8 次、搜索 2 次、模型 6 次、任务 90 秒；正文预算应核对并保持有界）。分批和规划消耗也计入，不因新方案自动扩大。

## 7. Harness、权限服务与 Evaluation 的职责

| 层次 | 必须负责 | 不可代替的其他职责 |
|---|---|---|
| Harness | 问题规划、可用工具、预算、阶段事件、答案证据和完整性 | 不替代数据访问前鉴权 |

| 后台页面 | 经授权查询运行、评分、反馈和版本比较 | 不新增业务 Agent 的后台查询能力 |

## 8. 运行记录与评估数据约定

优先复用 `agent_v2_runs/events/results` 及已有用量记录。增加字段/表前核对 schema，不复制整套聊天日志，不把大快照搬进评估表。

### 8.1 最小记录

| 对象 | 最低需要的信息 |
|---|---|
| 一次运行 | 运行/会话内部标识、渠道、实际应用版本、模型标识（已知才记录）、策略版本、开始/结束、阶段、运行状态 |
| 工具操作 | 模块/工具、允许或拒绝、原因类别、耗时、结果引用、必要覆盖摘要；无受限数据值 |
| 需求覆盖 | 子问题完成/部分/拒绝/未接入/失败，不等同于技术执行状态 |
| 评估结果 | 评估器及版本、规则、通过/失败/未执行/受阻、不适用、理由类别、证据引用、严重级别、评估时间 |
| 人工反馈 | 目标运行、提交者、评价类别、可选备注、复核状态、修订审计 |
| 评估批次 | 数据集/版本、应用/模型/提示及评分版本、环境、开始/结束、实际执行数和逐例结果 |

保持运行状态、需求覆盖和质量评分独立；程序正常结束不能自动置质量为通过。评分修订保留原值和修订记录，不覆盖证据。

### 8.2 隐私与权限

- 后台汇总默认不展示原始问答、账户、金额、客户等。查看原始内容需独立的后台详情授权，并满足结果来源模块权限；默认不足则脱敏或拒绝。
- 第一版默认仅现有管理员可直接进入；新增后台资源不得因普通部门权限默认分配获得访问。复用既有权限管理，具体资源名按代码惯例登记；不创造新角色体系。
- 页面、统计、搜索、明细、反馈和评估 API 一律不注册到 MCP。管理员经业务 Agent 查询同样拒绝。
- 评估数据不进入业务 Agent 历史上下文、公开搜索或业务数据目录。
- 业务 Agent 禁止读取后台不妨碍服务端写入必要遥测，也不妨碍获授权人员直接使用后台。
- 原始答案尽量通过受控引用读取；跨用户审核默认不显示正文，除非有明确的审阅授权。管理员角色不能被解释为对外发送所有正文的许可。
- 不新增自动删日志或清理原始业务数据。沿用已有保留策略；若无法满足存储需求，提出容量建议，不自行设定不可逆清理。

### 8.3 统计口径

- 查询窗口按北京时间，支持近 7 天、近 30 天、自定义；记录时间可 UTC 存储，API 和页面均截断到整秒，耗时小于 1 秒可显示“小于1秒”，不暴露小数秒。
- 一个用户任务算一次调用；模型重试/工具调用独立计数，不膨胀任务数。生产、评估回放、合成测试必须分组，正式使用总览默认排除评估流量。
- 成功结束率是技术指标；需求覆盖率和质量通过率分列。拒绝越权可能是正确结果，不等同于系统故障。
- 某项规则覆盖率 = 已有判定的适用运行数 / 全部适用运行数；通过率 = 通过数 /（通过数+失败数）。未执行、受阻、不适用分别列出，不计通过。
- 抽样评估显示样本数、抽样方式及覆盖率，不外推为全体准确率；没有反馈不是好评。
- 费用仅在有可靠供应商用量或明确版本价格时显示，估算须标估算；不可用显示未知，不能以零费用代替。任务费用和评估费用分列。
- 多模块运行总任务只计一次，模块统计可重复归属，页面说明模块合计可能超过总量。

## 10. 可执行 Evaluation

### 10.1 四种执行来源

1. 定义校验：只报告用例是否规范，名称不再使用容易混淆的 deterministic 表示业务运行通过；旧别名如保留必须明确弃用含义。
2. 离线确定性评估：通过临时数据库、冻结数据、脚本模型/模拟网络验证权限、边界、数值、展示和异常，不调用外部服务。
3. 受控真实模型评估：实际走 Harness 和 MCP，显式指定目标、身份、用例、预算；禁止把定义通过代替执行。生产真实数据用只读查询。
4. 人工评估：后台可审核具体回答，记录标准、结论和原因。LLM-as-judge 自动评分留待单独费用/隐私决策，本期不启用。

### 10.2 统一用例与执行结果

扩展已有用例结构，至少包含 id、需求编号、权限配置类别、模块接入状态、问题/多轮输入、fixture 或数据快照版本、允许/禁止操作、预期事实/容差/引用/覆盖、评分规则版本、严重级别。

结果至少包含 run_id、case_id、实际应用版本、输入数据版本、执行来源、每个断言判定、证据引用、错误类别、耗时/用量及预算受阻状态。结果显示的 expected/oracle 不得作为答案提示发给被测 Agent。

- 相同数据/权限下允许多种正确工具路径，不强制唯一调用序列；但禁止操作和必须取得的证据严格检查。
- 数值以确定性服务和冻结样本为判定基准，容差必须事先登记，不能为了通过临时放宽。
- 对实时网页检查来源是否存在、时点和结论支持；跨版本精确比较优先冻结正文。实时变化时标记不可直接比较。
- 关键语言用例可重复执行记录波动，次数受预算约束；预算不足标未执行，不重新计算已授权额度。
- 评分规则改版必须可追踪；旧/新规则结果不混算趋势。
- 支持失败记录转成脱敏候选用例；人工确认后纳入固定集，不能自动泄露真实业务数据或改写验收标准。

### 10.3 线上质量检查

默认以已有运行事件/答案校验信息做便宜的确定性检查，异步记录派生评分，使用运行+评估器版本去重。不重复调用业务工具或模型来回放每个生产请求。

第一版应覆盖：来源引用格式/归属、权限拒绝是否按预期、明确外部需求是否有公开证据、请求覆盖是否如实、预算终止说明。引用有效不自动证明解释正确；无法判断的内容显示待人工评估。
