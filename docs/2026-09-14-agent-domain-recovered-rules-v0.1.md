## 1. 结论与本次范围

持仓语义并非从未设计：历史用户对话明确过 Call/Put 净额、月份与方向分组、浮盈、价格和手续费规则，旧版 `closing_trading_review.py` 也已有相应实现。当前通用 Agent 的工具目录没有承接其中部分能力。

第一批 Domain 修复应恢复规则继承关系，将已有净额与分组语义接入当前有效持仓和实时估值链路。复用经核验的业务算法，不直接调用旧版固定账户、固定品种、日终结算报告来回答当前持仓。

本次只汇总持仓、期权数量与浮盈相关规则，附带其查询、展示和证据约束。公开研究、Greeks、现货期现保留现行能力边界，本次未全面审计其规则，也不据此扩展实施范围。

## 3. 可以直接继承的持仓规则

### D01 账户、资产与全量范围

V2 已确认首批为宏源全部期货与期权交易、持仓，使用服务端授权范围。不能沿用 V1 仅铁矿石期权的整体范围限制，也不能因为数据库存在其他账户而自动开放。期权专属指标只对期权计算。

全部持仓包含已归类与未归类的有效持仓，不等于期权台账已手动归类的子集。不把结算持仓与 WH6 成交简单相加；沿用有效事实层的去重、覆盖和持仓推算结果。已平仓部分不再进入当前持仓。

依据：S5、S7。跨品种展示保留品种、单位与范围，不把所有资产统一换成铁矿石万吨。

### D02 “现在”、历史和快照

“现在”默认最新可用持仓，不逐次询问。保留持仓数据截至时间、行情时间和查询时间的区别。汇总和组成使用同一持仓快照，缺少真实数据时间不得以查询时间替代。

历史结算结果保留结算口径，不能称为当时最后成交价估值；没有同期价格，不能用当前行情倒推历史浮盈。用户指定的日期没有数据时明确缺失，不能换成另一天后声称完成。

依据：S2–S5、S7。

### D03 总手数与净手数是不同指标

总持仓手数沿用当前范围内全部有效剩余持仓数量的加总。期权净额另按 Call、Put 分别计算，不能用总手数替代净卖数，也不能把净额当作全部持仓手数。

Call 净卖手数 = Call 卖出持仓手数 − Call 买入持仓手数。

Put 净卖手数 = Put 卖出持仓手数 − Put 买入持仓手数。

买入超过卖出时显示“净买”及正的数量，不显示负数“净卖”。旧代码对恰好抵销使用“净平”；净平不代表没有多空持仓，应同时保留底层组成。

依据：用户 S1 行 720；S2 第 3.3 节；S6 `_build_net`。净平标签属于已有实现，不能扩大解释为无风险。

### D04 跨月份净额与数量单位

同一品种的 Call 总量、Put 总量允许跨实际月份进行买卖数量抵销。月份、期权类型和买卖方向的组成不能丢失。

吨数按各持仓手数乘受控合约规格中的乘数计算后汇总，万吨为吨数除以 10,000。模型不能填写乘数。对当前铁矿石规则可输出手、吨、万吨；其他品种须保留其实际单位，禁止无条件转换为万吨。

数量抵销不生成交易、不开平重配，也不等于不同月份和行权价的风险完全抵销。

依据：S1、S2 第 3.3 节、S6。多品种单位隔离是将既有单品种规则接入 V2 时必须落实的工程边界。

### D05 分组与“对应浮盈”的已有含义

用户明确给出的基础分组是“实际合约月份 × Call/Put × 买卖方向”。每组展示实际行权价区间、总手数和该组全部实际剩余持仓的浮盈/浮亏；保留单合约明细供下钻。

2610、2611、700–740 都是示例，不是固定月份或行权价。没有持仓的月份或方向不生成空白占位组。

净卖是数量指标；盈亏先按每条实际持仓计算，再汇总到上述业务分组。不创建“把多空抵销成一笔虚拟净卖仓位，再给这笔虚拟仓位计算浮盈”的新规则。

如果用户明确要求只按 Call/Put 合计浮盈，可对相应类型的实际持仓浮盈加总，并清楚称为“Call 类持仓合计浮盈”或“Put 类持仓合计浮盈”；只问卖出部分时使用方向筛选。这是对已有分组结果的查询组合，不把它描述成用户此前指定的默认格式。原有证据足以恢复基础分组，不需要重新让用户在“全部多空”与“仅卖出”之间二选一。

依据：S1 行 720、1514；S2 第 3.1–3.2 节；S6 `_position_groups`。

### D06 当前浮盈计算与价格

多头浮盈 =（具体合约最新有效市场成交价 − 持仓均价）× 剩余手数 × 合约乘数。

空头浮盈 =（持仓均价 − 具体合约最新有效市场成交价）× 剩余手数 × 合约乘数。

使用已有有效事实层的剩余数量和成本，不在 Agent 层重建 FIFO 或用展示舍入后的均价回算。不扣手续费，不包含已经平仓的盈亏。行情价不能用账户最近一次自身成交价、标的价格或主力连续价格替代。

实时估值不回退结算价、中间价或成本价。临时持仓只表示事实尚未结算确认；具备有效数量、成本、乘数和行情时可以估值，并保留临时状态。

依据：S4 用户直接纠正与确认；S4 设计第 4.1–4.3 节；S7 `select_live_trade_price`、`calculate_live_position_floating_pnl`。

### D07 缺数据与部分结果

数量完整、行情不完整时，数量继续交付。部分合约可估值时标为“已估值部分浮盈”，保留已估值和应估值记录覆盖情况；全部无法估值时返回不可用，不能填零。

刷新失败时只可沿用此前真实取得的有效成交价，并说明沿用及真实行情时间。没有此前有效行情时仍为不可用。净额依赖的合约类型、方向或数量缺失时，不能默默排除该行后把结果称为完整。

依据：S4、S7。最后一项为完整性原则在净额计算上的直接应用。

### D08 平仓盈亏与持仓浮盈分离

真实平仓盈亏不扣手续费；持仓浮盈只针对尚未平仓持仓。两者分别保存和表达，不合并为含义不明的“总盈亏”。当前持仓总浮盈可汇总各持仓组的实际浮盈，但不可与平仓盈亏混算。

用户只问一类指标时只回答该类。既有自动日报包含两个分别标注的总数，不意味着所有单项问答都必须附上两个总数。

依据：S1 行 756、1514；S2 第 4.1 节；S3 第 3–4 节及自动结果规则。

### D09 归属与事实口径

没有标签就没有已知组别，Agent 不猜测。历史分组只使用当时可验证的归属，不能以现在的归属替代。事实持仓、事实盈亏与业务归属台账的特殊计算是不同口径；本次净额及实时浮盈修复沿用事实口径，不改写业务归属或台账规则。

依据：S5；既有交易总览统计口径；S7。

### D10 回答形式与内容范围

当前用户的展示要求优先。纯文字请求在生成、修复、兜底中均不得被表格替代；需要详细分组时可用自然语言逐组表达。无指定格式时按信息量选择，不能恢复 V1 固定模板覆盖所有回答。

用户曾明确：默认不必拆成“毛亏损与盈利抵消”，不主动解释未询问的逐笔抵销。只问手数时不强行附加盈亏或 Greeks；需要整体摘要时才组织相关完整内容。

依据：S1 行 1514；S3 相关性规则；S5 V2 对旧版的替代关系；S8。

## 4. 已有实现与当前接入缺口

- 旧收盘服务已有 Call/Put、月份、行权价解析，净卖/净买/净平及吨数换算，按月份/类型/方向的浮盈分组。旧测试已包含跨月份买入大于卖出等预期。它依赖固定宏源、铁矿石和日终结算协议，不能整体拿来回答当前持仓。
- 当前有效事实与行情链路已有逐条实时浮盈和完整持仓快照。应保留这条来源、成本与价格链路，复用净额和分组规则。
- 当前 Agent `catalog.py` 没有 Call/Put、合约月份和行权价等期权业务维度；持仓指标目录没有净买卖和吨数换算指标。
- `FactQuery`、`PositionArgs` 没有 Call/Put 筛选；汇总只接受当前登记维度与指标。模型不能可靠地组合此前已确认的期权业务问题。
- 证据协议和展示投影也必须识别新增维度及计算结果，否则只增加底层算法仍然可能答不出来。
- 当前表格兜底不接收展示偏好，违反纯文字要求；这是后续展示修复点，不应靠修改业务口径解决。

## 5. 不再向用户重复确认的事项

净卖是否减去买入、净买怎样显示、是否跨月份净额汇总、是否保留月份与方向组成、平仓和浮盈是否分开、是否扣手续费、当前使用最后成交价还是结算价、临时持仓能否估值、缺行情是否填零、“现在”的含义、未归类是否计入、是否允许纯外网问题、是否限制固定题库：已有足够记录，按上述依据继承。

## 6. 尚需核验但不应转成业务重复问答的事项

1. 当前真实持仓有哪些合约格式、单位和行情缺口；现有解析和合约规格能否完整覆盖。这是工程与数据核验。
2. 净额、分组浮盈和文字引用在新 Agent 工具/证据层的接入方式。这是实现责任。
3. 历史某次失败究竟在哪个环节发生。需要实际运行证据，不能只凭本轮代码盘点下结论。
4. 既有实现使用浮点数和舍入的具体影响。复用业务规则时需核对现行金额精度与汇总一致性，不把界面舍入值当计算输入，也不借此扩大为全系统重构。

本次基础持仓数量与浮盈修复未发现必须重新询问用户的阻塞业务问题。

## 7. 发现但暂不阻塞本批修复的历史差异

贡献比例存在记录差异：原始问答中用户接受过“亏损贡献按毛亏损作分母”，早期设计和后续实现又出现按净盈亏及抵消警告的表达。当前没有足够依据将二者统一成唯一默认指标。本批不新增或修改贡献比例；日后修复归因时先区分“亏损贡献率”与“净盈亏贡献率”，仍无法消解的默认含义才请用户确认。

旧版“仅八类问题、仅铁矿石期权、仅结算数据、固定模板、不支持公开问答”已被 V2 在对应范围内替代，不是本次需要重问的冲突。旧版收盘价格时间和实时刷新故障标记属于不同场景，应分别保留适用条件。

## 8. 据此修正后的首批实施与验收依据

实施次序：核实最新开发基线与隔离工作区 → 将已确认的期权维度与净额计算接到当前有效快照 → 完善工具筛选/分组/指标与证据引用 → 核验问答范围与缺项 → 以指定文字形式验收。保留既有历史结算服务，不把旧估值口径带入实时回答。

首批必须覆盖：Call/Put 分别净额；净买、净卖、净平；多月份、多行权价、多空并存；不同查询范围；未归类持仓；部分缺行情；确认无持仓与数据未知；实时/历史口径隔离；平仓/浮盈分离；完整快照与分页一致；只问数量不超答；纯文字且每个业务数字可引用。

验证分层记录：确定性计算核对、模型组合问答、真实管理员页面验收。已有测试内容不代表本轮已运行；本轮规则汇总也不代表上述验收完成。后续正式验收继续遵循 `scripts/admin_acceptance.mjs` 和当前有效发布授权。
