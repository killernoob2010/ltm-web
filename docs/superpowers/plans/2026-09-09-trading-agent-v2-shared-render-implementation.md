# 交易 Agent V2.1：同实例部署实施计划

日期：2026-09-09。状态：设计已确认；S1–S3 的本地适配与回归已完成，S4–S7 的 Staging/真实联调与发布验收未完成。单主 Agent 执行，不派生子 Agent。

依据：[完整设计](../specs/2026-09-09-trading-agent-v2-shared-render-design.md)、[V2 技术合同](../specs/2026-09-09-trading-agent-v2-technical-contracts.md)。本计划接续旧 T0–T10，替代旧 T11 的默认独立主机安排；旧测试只是历史证据。

## 范围与授权

目标：现有 Render 服务容器内 Web + Agent 独立进程，固定计算套餐不变，完成非生产验证后形成可审阅的正式发布包。业务范围、只读限制、数据口径不变。

本次执行已修改原 Agent 模块、相关测试、依赖、启动脚本和文档，未改其他业务页面或计算公式；未修改云配置、生产环境变量、数据库或套餐。Staging 迁移、真实凭据联调、生产部署和付费操作仍按门禁另行处理。

## S1：核对当前实现与部署合同

- [ ] fetch 并核对最新 staging/main、隔离分支差异及环境映射，保留其他人的修改；不能按旧提交盲推覆盖共享 staging。
- [ ] 核对 Web Python/依赖、Render 构建与启动命令、任务消费、数据库连接方式、单实例锁和现有开关。
- [ ] 核查 MCP 默认参数、结果引用路径、搜索私有上下文及安全读取、总期限和重试、实际企微配对/回复链路；发现缺口仅修订本范围。
- [ ] 明确同运行时双虚拟环境可行性；不兼容时停止依赖变更，提出最小替代方案。

证据：当前合同差异表及明确文件清单。完成条件：所有 V2.1 要求有对应实现或待修改项，历史本地通过与真实未验收分开。

## S2：构建、启动和资源控制

责任：render_start.sh、必要新增构建/进程管理入口、requirements-agent-v2.in/.lock、backend/app/trading_agent/worker.py、harness.py、store.py、相关测试；不修改生产 Dashboard。

- [ ] 本地/独立 worker 可分别构建虚拟环境；Render 同实例按根目录依赖构建，执行 pip check 与实际 import，并确认 Web 依赖不受 Agent pin 影响。
- [ ] 默认 Agent 关闭，启动一个 Web 和一个 Agent；MCP 不暴露公网，无重复项目调度器。
- [ ] 实现 Agent 有限重启、Web 独立存活、信号传播、停止接单及可终止任务。
- [ ] 落实串行、有限队列、队列过期、容器总资源保护与恢复阈值；外部重试全部计入预算。
- [ ] 限制数据库连接和长事务；记录可验证的 Agent 就绪状态。

测试：真实子进程启动/退出、故障循环、默认关闭、Web 退出、Agent 退出、任务期限、内存/CPU 保护状态转换。完成条件：关闭 Agent 与故障 Agent 均不导致主动重启 Web；明确同容器 OOM 仍属共享风险。

## S3：云端单实例与交互恢复

责任：worker.py、store.py、企微适配、必要配对入口及 tests/agent_v2。

- [ ] 使用实际支持会话锁的连接实现环境 + bot 单主锁，失锁停消费者；不以文件锁替代。
- [ ] 两个独立进程竞争同 bot，验证唯一消费者、数据库断连失锁、新进程接管。
- [ ] 原子任务领取、重复 msgid 去重、queued 恢复、running 中断终态、令牌撤销和发送未知状态。
- [ ] 本人 wangjingze 网页配对到企微真实身份，群/其他身份拒绝；核实 SDK 消息及回复窗口。

完成条件：受控重启不重复模型请求或回复；未知投递不包装成送达；配对可由真实用户路径完成。

## S4：Staging 数据与真实功能联调

- [ ] 核对 Staging 配置是否实际存在，不因本地缺变量推断云端没有配置；不读取输出密钥。
- [ ] 迁移前目标备份、恢复核验；按旧技术合同显式执行六张附表迁移和权限回读，不跑全库初始化。
- [ ] 固定快照核对全量持仓/浮盈亏/Greeks，既有网页业务回归。
- [ ] 在已授权 API 额度内，真实 DeepSeek → MCP → Staging 数据 → 本人企微 → 追问证据；包含未预设工具组合与公开研究。
- [ ] 通用 Harness 回归、真实留出题及人工答案抽检，沿用旧 T10 硬门槛和评分；不新增关键词路由以过题。

完成条件：真实路径证据齐全；免费 Staging 仅记功能联调，不记全天在线。缺真实配置仅阻塞相应子步骤。

## S5：共载与恢复验收

- [ ] 非生产同配置限制为 1 CPU/2 GB，Agent 关闭/开启各测同一数据与请求组合。
- [ ] 组合负载至少 30 分钟，检查网页业务、p95、错误率、总资源、队列及最大支持情景；按设计第10节门槛判断。
- [ ] 受控测试进程崩溃、发布重叠、网络中断、终止信号和发送未知；不在生产注入故障。
- [ ] 记录平台终止宽限、依赖构建、重连机制的实际核验；本地限额测试不能替代 Render 云端观察。

完成条件：无新增 Web 错误/OOM，延迟和内存余量满足门槛，问题有可解释终态；超标先优化，不能自动购买资源。

交付具体不可变代码版本、非生产证据、受影响入口、数据库变化与备份恢复、Render 配置名称（无密钥）、实际收费影响、关闭 Agent 和整版回退方案，以及真实云端待观察项。

- [ ] 复核 Dashboard 的套餐、实例、实际负载和计费条件未发生变化。
- [ ] 非生产代码/功能验证通过后请求正式发布确认；不提前修改 main、生产配置或生产数据。
- [ ] 确认内容明确包含生产默认关闭部署、必要附表迁移及仅本人启用；未授权部分不执行。

## S7：批准后的本人试用与观察

- [ ] 按批准版本部署，先验证 Web 业务，再启用本人 Agent；维持 1 实例、原套餐。
- [ ] 验证正式身份、账户范围、实际企微问答与证据；不将 Staging bot/令牌复用到 Production。
- [ ] 实际观察至少 24 小时的 Web、Agent、资源和费用趋势，记录时间窗口及监测来源；未完成观察明确待验收。
- [ ] 异常关闭 Agent 并按批准回滚方案处理，不删附表；完成部署后更新版本记录及精简交接。
