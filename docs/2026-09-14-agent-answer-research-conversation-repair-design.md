## 1. 目标与边界

用户应能通过自然提问取得真实授权数据、按需查询公开资料，并得到符合所问范围及展示要求的答案。查询成功、计算正确、答案正确、页面可用必须分别验证。左侧对话历史改为顶部页签，一段对话对应一个页签，× 删除、＋ 新建，下方问答内容使用完整可用宽度。

本次统一范围为五个修改包：A 答案正确性与证据；B 公开查询；C 展示偏好；D 连续追问；E 对话页签与宽度。已完成的 Domain 计算能力作为基线保护，尚缺的请求范围检查纳入 A/D；不把本轮方案描述成重新开发全部业务领域。

## 2. 证据等级与检查结论

本轮只读检查基线代码，以 AST 抽取现有纯函数和正则在本地运行复现；没有连接数据库、调用模型或发起搜索。下面“复现”是确定性代码行为，不冒充正式版问答验收。

此前会话的真实页面记录 #104、#105 均显示持仓和行情读取、query_positions 调用，以及两次 unreferenced_number 后文字兜底。这能证明当时执行了取数链路，但不能确定失败草稿中是哪段文字触发校验。上一轮把错误直接归因为“模型没绑定数字”证据不足；当前诊断应保持开放。

### D01 数字证据检查存在合约月份误判（P0）

- 位置：`backend/app/trading_agent/answer_v21.py` 的 `_business_number_without_tokens`、`_business_number_matches`、`_CONTRACT_TOKEN`。
- 本轮复现：`2701铁矿石期权总手数 {{fact:00000000-0000-0000-0000-000000000001#/metrics/quantity}}` 返回未引用数字 True；改成 `i2701期权总手数 ...` 返回 False。
- 结论：裸合约月份会被视为业务数值；即使数量已绑定，整段也可能被删除。不能据此断言 #104/#105 就是这个原因，缺少当时失败草稿的精确定位。
- 另需检查数值表达的边界：当前字母数字 token 排除较宽，不能通过把数量连上英文单词就逃避事实校验。

### D02 正常答案的纯文本转换会丢负号（P0）

- 位置：`answer_v21.py::_plain_text`。删除 Markdown 符号的字符集合包含 `-`，对整段全文替换。
- 本轮复现：输入 `浮盈亏 -347810 CNY`，输出 `浮盈亏 347810 CNY`。
- 影响：正常验证答案的 plain_text 可能把亏损变正数；前端当前正文取 body_markdown，不能直接推断视觉正文也错。持久化、历史、其他纯文本消费端须逐个核验。此前兜底直接写 plain_text，不能用兜底保留负号证明正常路径正确。

### D03 缺少持仓“问题与结果范围”闭环（P0）

## 3. 目标链路与最小接口

沿用现有模型调用、白名单工具、结果存储和答案协议。增加下面两份小型结构化合同，优先使用已有 JSON 载体，不新建规划服务或数据库表。

### 3.1 ResolvedRequest：本轮实际请求

字段：业务域、内部/外部/混合/通用解释意图、过滤条件、所需指标、分组、排序、展示模式、禁止的展示形式、是否刷新、继承的结果引用、各条件来源（本轮明确/上一轮继承/默认）。服务端身份及授权独立计算，不能由模型填入。

来源规则：明确新条件覆盖旧条件；未提及条件继承；显式清除按对象处理；语义不明且会实质改变结果时询问一个最小问题。模型解析后的合同仍须对照用户原文做检查；合同校验不等于自然语言理解正确，必须有留出问答验收。

“全部期权”清除 Call/Put 与方向筛选；按原 Domain 基线，已明确月份保留。只有“所有月份”清除月份。“只说数量”改指标不改资产范围；展示偏好继续继承。

### 3.2 AnswerCoverage：本轮回答覆盖

每项必答内容记录：期望过滤/分组、指标引用、数据状态、覆盖行数、来源时间、最终交付位置或缺失说明。持仓范围匹配、所有必答指标存在、单位/正负正确、展示满足约束才可标完整。

这两份合同是设计新增项，不声称已在上一轮 Domain 实现。持久化优先在现有 structured_payload 内使用可选版本字段；检查 API schema、历史读取、前端兼容后再接入。不得静默丢弃字段；若现有 schema 无法兼容，先回到设计评估。

## 4. 按顺序可执行的修改包

### A. 答案生成、证据检查与数值保真

允许组件：answer_contracts.py、answer_v21.py、prompts.py、harness.py、presentation.py；相关单元与链路测试。

1. 先为 D01/D02 增加失败测试。数字检查统一到同一套词法判定，区分业务量与有来源的标识值。
2. 合约月份只能在已验证请求范围/结果维度中绑定为标识；推荐增加受限标识引用，或者从已验证的 selection 建立标识上下文。不能豁免所有四位数、把未绑定金额改成 knowledge，或只为 2701 写特例。
3. 工具投影提供所需事实的可用引用清单（稳定路径、标签、单位、状态、所属维度）。模型使用引用组织文字，服务端替换数值；不按数值相等自动猜测引用。
4. 用结构感知的纯文本转换保留负号、小数、日期及范围连字符。核对 body_markdown→plain_text→存储→历史→页面，浮亏不得在任何消费端变为正数。
5. 校验失败保留安全的定位：block id、错误种类、字符范围、标识/数值类别、允许引用路径；沿用事件载体，不保存密码、密钥、整份原始模型响应或内部数据到普通日志。若需要生产复现，先落该诊断再提新问题。
6. 唯一一次修复针对具体失败片段，尊重展示要求；兜底只覆盖请求指标，明确查询范围、必要时点和缺项。完整性不足保留 partial；不能将 fallback 一律升级 complete 来消除告警。
7. 将 AnswerCoverage 接入持仓查询和复用结果的最终检查，漏组/漏指标/范围错分别报错。

### B. 公开查询与内外部任务分流

允许组件：research_policy.py、harness.py、prompts.py、research.py，必要的只读 public_transport 接点；不换搜索供应商、不调生产配置。

1. 分开“主题”和“数据来源意图”。明确公开新闻/财报/官网问题应得到纯外部计划，不能因为出现库存/发运就强制内部查询。
2. 保留禁止联网的硬约束、权限和出站校验。对自然语言识别采用有界结构化分类，复用现有首轮模型预算；简单明确请求可确定性识别。模型只能提出候选，不能自授搜索或内部账户权限。低置信且涉及私有信息时保留澄清。
3. 公共实体白名单来自用户明确公开主题及受控公开品种/港口目录；不得由模型或网页文本随意声明“这是公开的”。私有数量、客户、账户、订单、持仓组合继续拒绝出站。
4. 公开子问题从请求构建，尽量不喂入私人结果；混合问题按来源分开取数。外部成功但内部失败、或相反，都保留成功部分。
5. 分开记录未请求、策略禁止、未配置、鉴权失败、限流、无结果、正文失败和证据失败。能搜索不等于已读正文；摘要不能作为已经核验的全文事实。
6. 来源引用保留真实链接、获取状态、来源日期；纯外部回答不添加“内部数据已保留”等无关提示。配置存在只代表可尝试，不能写成服务可用已验证。

### C. 展示偏好与适量回答

允许组件：position_semantics.py 中现有偏好接点（逐步委托给共享偏好解析）、prompts.py、answer_v21.py、harness.py、frontend/agent_answer_renderer.js。

1. 区分 prose/list/table/chart/auto，禁用形式单独表示。“不要表格，画图”是 chart + 禁止 table；“列表”是文本条目。
2. 当前明确要求优先，其次沿用会话偏好；无要求时简短结论优先用文字，多对象比较或趋势可选择表格/图。自动模式不等于默认表格。
3. 删除通用提示中固定业务指标和固定表格指令，改为按请求选择的小段策略；纯外部文字问题不能被注入 Call/Put 模板。
4. 正常、修复、兜底、恢复历史四条路径共用相同展示约束；检查实际 DOM 表格/图形及正文 Markdown/HTML，不能只检查 views 数组。
5. 仅换展示复用同一授权且未过期快照。视图需要新聚合时从已保存全量行确定性计算，不重新取行情。结果过期需说明后重新查询，不能假装同一快照。

### D. 连续追问与结果上下文

允许组件：contracts.py/answer_contracts.py、store.py、prompts.py、harness.py、facts.py 的已有结果汇总接点。

1. 每轮合并 ResolvedRequest，并保存每个条件的继承/替换来源；模型不靠最近一句问题重新猜全套条件。
2. 结果目录保留可复用全量范围、当前子集、来源/截至时间、展示偏好和必答指标；不把被筛窄的 Put 结果当全部期权。扩大范围时回到仍可访问的原始完整快照，不能对局部行补零。
3. 工具压缩优先保留本题所需指标、范围、引用、覆盖和时点，再裁剪预览。超限明确列出省略部分与可用读取方式，禁止给模型只有 UUID 却期待它生成具体数字。
4. “刷新”取得新快照并替换当前引用；不同快照不混算，权限/所有者/会话/有效期每次再次检查。

### E. 顶部对话页签与内容宽度

允许组件：`frontend/index.html`、`frontend/closing_review_agent.css`、`frontend/closing_review_agent.js`、必要的 `frontend/agent_answer_renderer.js` 和对应前端测试。仅在助手选择器范围调整样式；共享 styles.css 只有证明助手祖先容器影响宽度时才做定向改动。复用当前会话列表、创建、删除、恢复和任务查询接口，不重做后台会话系统。

#### E1 布局与宽度

布局顺序为：页面标题 → 单行页签栏（可滚动页签＋固定新建按钮）→ 可滚动消息区 → 输入区。系统业务导航继续保留；移到顶部的是助手内部对话历史。原对话历史不再占左侧列宽。

- 当前页签高亮，完整标题通过悬停和可访问名称提供；长标题省略。沿用已有用户标题，不覆盖；空标题显示“新对话”，默认重名可用已有时间作辅助区分，不额外调用模型命名。
- 新对话插入页签末尾并选中；本轮会话内顺序稳定，不因回答更新不断重排。重新加载可采用服务端既有顺序，暂不增加拖拽排序或排序持久化。
- 页签过多只让页签轨道横向滚动，选择项自动进入可视区；＋始终可见。不得固定只显示前几个对话而无法访问其余历史；若列表接口分页，则保留加载其余对话的操作。
- 助手回答卡片允许利用完整内容宽度；用户问题卡片可保持较窄。普通文本、长链接、连续字符能够换行；不截断正文或使用省略号隐藏答案。
- 明确 workspace→page→layout→messages→message→view 各层的 min-width/min-height 与 border-box。消息区负责纵向滚动；表格、代码块负责自身横向滚动；页面不被撑宽。
- 图形按容器宽度重新布局，标签、图例、来源、详情入口可达；不单靠裁切 SVG 隐藏越界。不支持狭窄展示时使用图形自身可控滚动或清晰的切换入口。
- 输入区在助手内容区域底部独立占行，随窗口高度调整；不能覆盖最后一条回答、来源详情或撤销提示。用户已向上阅读时新内容不强制拉到底部；在底部跟随时保持跟随。

#### E2 新建、切换与异步状态

- ＋调用现有创建接口，成功后出现并选中新页签、聚焦输入框；请求中禁用重复创建，失败保留原页签和草稿并给出可重试提示。
- 按 conversationId 保存当前会话内的草稿、滚动位置、发送状态、任务 id、进度和读取请求版本；切换先保存再恢复。草稿只在页面内存中保存，不新增浏览器敏感数据持久化；刷新页面后恢复服务端消息，不承诺未发送草稿跨刷新保存。
- 当前对话生成中仍允许切换、阅读其他对话或准备草稿；后台任务不因切换取消。异步结果只能更新所属对话的缓存与页签状态，不能写进另一页签。
- 仅为已有活跃任务保留有界轮询，不为每个空闲页签启动轮询。回到该页签能取得已完成回答；刷新页面后从服务端重新发现任务状态。
- 不扩大后端同时运行限制：如果另一个对话已有任务且后端不支持并发发送，只限制新的发送并说明已有任务进行中；仍允许切换与新建。不能通过前端重复提交绕开额度或幂等保护。

#### E3 × 删除与撤销

- × 明确定义为删除对话，不是仅关闭可见页签；辅助名称为“删除对话：标题”。对普通已结束对话单击即可删除，取消原额外确认步骤，并提供明确撤销入口；沿用既有可恢复删除接口，不做物理清除。
- 删除当前页签优先选右邻，无右邻选左邻；删除非当前页签保持当前对话不变。删除最后一个显示空白新对话状态，避免加载历史时自动创建无意义记录；首次发送或点击＋再创建。
- 删除失败保留原页签、选中项及草稿；请求未完成前防止重复删除。撤销成功恢复原对话及同一页面内保存的草稿和位置，撤销失败如实提示。
- 连续删除多段对话，每次都有对应的撤销记录，不允许后一条状态提示覆盖前一条的唯一撤销入口。恢复窗口以既有服务端保留策略为准，不虚构永久可恢复。
- 生成中的对话本批禁用 × 并解释“回答生成中，结束后可删除”，其他页签可以删除。此规则避免把删除误做取消任务；新增取消后台任务能力不在本方案范围。
- 页签和删除按钮是独立可聚焦控件，不能嵌套 button；使用 tablist/tab/tabpanel 关系、aria-selected、明确焦点。方向键切换页签，Enter/Space 激活，键盘可操作 × 与＋，删除后焦点进入相邻项或＋。
