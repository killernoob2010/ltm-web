## 已发现缺口

- 旧设备绑定在服务端仍记录为客户端 `0.1.0` 时，0.3.0 会直接获取策略并调用上传，但没有先调用 `/device/heartbeat` 上报新版号；服务端因此以 HTTP 426 拒绝上传。
- 本次仅在 Staging 使用现有 Windows DPAPI 设备令牌补发一次 `client_version=0.3.0` 心跳后完成验收。该动作没有新建设备、没有输出令牌，也没有改动业务事实。
- PowerShell 5.1 直接 `Get-Content` 读取无 BOM UTF-8 中文配置会产生错误解码；诊断时应使用 `[IO.File]::ReadAllText` 或显式 UTF-8。配置文件本身可被 0.3.0 的 Python UTF-8 读取。

## 下一步建议

1. 在采集器正式上传前自动调用心跳，并携带 `CLIENT_VERSION`；为“旧绑定版本低于最低版本、升级后无需重新配对即可恢复上传”增加回归测试。
2. 构建下一修订版 Windows 安装包，在同一虚拟机撤销人工心跳前置条件后重做覆盖安装、重启自动运行和全链路验收。
3. 单独核对 2026-09-07 的 84 条记录是否为夜盘业务日期；只有当服务端当前交易日策略推进或业务明确确认日期口径后再允许上传。
4. 若需要持仓验收，先确认 WH6 实际生成的 `position.dat` 来源，再验证完整快照；不得用成交记录推算替代。
