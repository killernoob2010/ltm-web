## 1. 目标与边界

本模块在现有轻量化交易管理系统中增加一级导航“贸易台账管理”和二级页面“现货业务台账管理”。页面以销售合同商品明细为记录粒度，接收销售合同跟踪表的“现货 + 生效”数据，维护现货业务台账 A:AY 51 个字段，同时保留人工补录、待补录、同步异常、历史迁移、战略套保手工记录和 Excel 导出。

本期明确不做实时同步、手动立即同步、字段修改审计、待历史匹配、复杂部分套保、期货系统接入、真实交易操作、生产环境变量、生产数据库、正式数据迁移或 Production 部署。

2026-08-25 已在用户授权的登录浏览器内只读确认正式销售合同 JSON 列表接口使用 Bearer 认证，并从统一认证页面及前端代码确认“登录页公钥 RSA 加密密码 → 一次性 code → Bearer 令牌”的个人账号登录流程；令牌失效后通过同一流程重新登录一次，不复用个人浏览器会话。真实 HTTP 适配器只使用已确认的请求、响应、字段和认证 contract；认证缺失或失败时任务以 `auth_unavailable` 明确失败，不猜请求协议、不读取业务网页 DOM、不把 fixture 结果标为真实同步。普通服务端 HTTP 客户端从当前开发网络访问认证页被源站防护返回 403，因此 Render Staging 能否完成该流程仍需使用用户个人凭据做一次只读验证；该验证结果是自动同步启用前门禁。

## 3. 业务数据模型

### 3.1 记录身份

`spot_ledger_records.record_id` 为模块内部主键。现货记录的业务唯一键为销售合同商品明细 ID，保存于 `source_detail_id` 并加唯一约束；不使用销售合同号单独做主键。战略套保记录使用模块生成的 `strategy:<uuid>` ID，完整开仓/平仓字段保存在同一行。

记录同时保存：

- `record_source_type`：`现货同步` 或 `战略套保`；
- `is_active`：当前有效标识；
- `supplement_status`：`已完成` 或 `待补录`；
- `missing_fields`：JSON 字段名称数组；
- `sync_status`：`正常` 或 `异常`；
- `last_synced_at`、`sync_error_summary`；
- `source_payload_json`：仅保存当前源记录的非敏感标准化快照，不保存凭据。

同步任务另存于 `spot_ledger_sync_runs`，包括 slot、时间、状态、页数、记录数、插入/更新/隐藏数和脱敏错误摘要。任务表不记录人工字段变更历史。

### 3.3 映射与计算

- `E` 使用量归属组；`AP` 使用业务毛利归属组；两者不一致只计算 `AQ=是`，不产生同步异常。
- `A=业务台账-<销售组别>`；`B` 为同销售组现有最大序列加一，不重排历史空档。
- `U` 统一使用签订日期；`G` 使用资源日期。
- `L` 和 `X`：合同已结案且结算数量有效时使用结算数量，否则使用合同数量。
- `D`：按销售合同商品明细 ID 回接正式源报表的 `业务类别` 完整原文，不做本地代码转换；源字典中 B05、B07 各存在多个完整类别，裸代码不能推断为落地货。只有完整原文明确包含“落地”或属于明确的 B09 系列时才计算为落地货；源端没有完整原文时保留代码并产生同步异常，不软隐藏旧记录。
- `F` 和 `Q` 使用显式维护的名称映射；未命中保留原始全称并生成映射提醒，不截断。
- `AG` 去除 `920109_` 等数字前缀；其他原始值保持。
- `K` 空值及 `--`、`***`、`---`、`**`、`****` 视为缺失；源系统后续有有效船名时覆盖临时人工值。
- `P` 仅船货-落地适用；该类型要求选择是/否，选择是时 `long_contract_object` 必填；其他类型保持空白。
- `AS` 为销售日期所在月首日；`AT` 在有跨月利润确定日期时取该月份，否则取 AS。
- `AU` 使用商品分类字典；未命中显示原值并标记校验异常。
- `AV`、`AW`、`AX`、`AY`为只读校验字段，不把非必填人工空值转成待补录。没有业务适用性时保持空白。

## 4. 来源适配与同步

### 4.1 标准化 source contract

同步核心只接收标准化 `SalesContractRecord` 字典。真实报表字段必须由已经验证的 profile 明确映射到标准字段；核心逻辑不按列序、模糊名称或网页 DOM 猜测字段。fixture 使用同一标准 contract，文件名和运行结果明确标为 `fixture`。

profile-driven HTTP adapter 只支持用户已确认的 POST 候选地址；它要求显式提供 request body、分页参数位置、记录路径、总数路径、页数路径、认证提供器和外部字段映射。2026-08-25 经用户授权在登录浏览器会话内做一次只读复核，确认报表路径为 `/jmreport/show`、报表 ID 为 `1055351755192311808`，请求体包含 `apiUrl`、`id` 和 JSON 字符串 `params`，其中使用 `pageNo`、`pageSize`、`periodDate`、`releaseDate`、现货、生效及 7 个销售组筛选。记录路径为 `result.dataList.TJJLYSHZ.list`，`result.dataList.TJJLYSHZ.count` 为记录总数，`result.dataList.TJJLYSHZ.total` 为总页数。响应行以中文字段名返回，已按需求说明书 8.2 的来源口径映射销售合同商品明细 ID、组别、类型、公司、日期、商品、港口、模式、船名、数量、价格、供应商、人员、客户和合同号。适配器内置该脱敏 profile，不按网页列序推断，也不保存真实响应或业务明细。2026-09-04 Staging 验收确认运行网络暂时无法连接该报表域名；已登录状态下把同一路径替换到 `tds-api.ejianlong.com` 会返回 404，因此不得把 API 主机误当成报表网关。

同日进一步只读确认销售合同页面调用 `POST https://tds-api.ejianlong.com/tradeing/saleContract/saleContractList`，响应为 JSON，请求使用 Bearer 令牌；统一认证登录页提交 RSA 加密密码到 `POST https://server-auth.ejianlong.com/login/pwd`，取得一次性 code 后通过 `GET /login?code=...` 换取 Bearer 令牌，未观察到独立 refresh token。个人账号作为授权主体已由用户确认；服务端只从 Secret 读取工号和密码并保存在进程内存，令牌过期或响应重定向到登录页时至多重新登录一次。不得提取或复用个人浏览器 Cookie，凭据、票据、令牌、认证响应和源业务响应均不得写入仓库、前端、导出或日志。

正式销售合同 JSON API 负责范围、关系及其他已确认字段；销售业务 AF 读取已匹配需求详情中的 `workManName`（需求业务员），不得读取合同详情中的同名经办人字段，也不得依赖候选报表。销售类型 D 的完整原文仍以 `POST https://tds-report.ejianlong.com/jmreport/show` 的已确认 JSON 报表 profile 按销售合同商品明细 ID 做只读回接，不再由本地映射表改写。Staging 验证先判断个人账号服务端登录能否成功，再判断同一内存会话和 Bearer 令牌能否读取候选报表；任一步失败均保留旧记录、不软隐藏，并在对应记录标记脱敏同步异常，不宣称销售类型原文回接完成。

### 4.2 全量扫描门禁

同步每个时点按 7 组、现货、生效条件全量读取分页，验证页序、总页数、总记录数、明细 ID 非空且唯一。只有验证完整成功，且记录处理没有导致整体事务失败，才将本次未出现的现货 ID 标记为 `is_active=0`。接口、鉴权、分页、解析或整体写入失败时保留旧可见记录，并写入异常 run。

同一明细 ID 重复扫描只更新系统字段；人工字段不被常规同步清空。系统优先字段只有在源有有效值时覆盖人工临时值。同步异常记录保留原始标准化值和定位信息，下一周期可重试。

### 4.3 调度

调度时区为 Asia/Shanghai，slot 为每天 09:00、10:00、11:00、12:00、13:00、14:00、15:00、16:00、17:00、18:00。模块启动默认不启用；只有 `SPOT_LEDGER_AUTO_SYNC_ENABLED=true` 且 source mode 配置完整时启动。服务在同步时段内启动时仅执行最近一个已到 slot，不补跑此前 slot；19:00 后启动不执行当天补跑。页面不提供手动立即同步按钮，只显示调度和最近一次结果。

## 5. 权限与 API

模块 code 为 `spot_ledger`，贸易处用户默认可查看/普通编辑权限；人工字段 API 进一步要求 `can_sensitive`，因此只有具备敏感操作权限的贸易处人员和管理员可以修改。查看、筛选、待补录和异常不扩大既有查看权限。编辑不调用操作日志，符合“不做字段修改留痕”；同步 run 与错误摘要仍保留。

主要接口：

- `GET /api/spot-ledger/field-definitions`
- `GET /api/spot-ledger/records`
- `GET /api/spot-ledger/records/{record_id}`
- `PATCH /api/spot-ledger/records/{record_id}`
- `GET /api/spot-ledger/pending`
- `GET /api/spot-ledger/sync-errors`
- `GET /api/spot-ledger/sync-status`
- `GET /api/spot-ledger/export`
- `POST /api/spot-ledger/strategic-hedging`

`records`、`pending` 和 `sync-errors` 均为服务端分页，默认 20 条，前端只提供 20/50/100 条三档并通过 `limit + offset` 请求当前页；后端拒绝超过 100 条的普通列表请求。列表接口只返回表格摘要字段，完整 51 字段仅在读取单条详情时返回；源标准化快照和同步任务原始错误明细保留在服务端，不进入列表、详情或同步状态响应。Excel 导出是用户明确触发的独立全量批处理，不复用普通列表页大小。

不提供手动立即同步 API。fixture 同步仅通过本地开发脚本/测试调用，不暴露为业务页面按钮。

## 6. 历史迁移与战略套保

历史导入按销售合同号、商品名称、销售价格、合同数量或结算数量匹配。唯一匹配只迁移人工字段，系统字段取当前源值；无匹配或多候选不迁移人工字段，不产生待历史匹配。`——`等占位值不参与匹配。旧“是否长协”同时含是/否与对象名称时拆成 P 和长协对象，无法确定则留空。迁移命令默认 dry-run，`--apply` 才写入本地/指定非生产数据库。

战略套保一条记录保存完整开仓/平仓字段，只支持全开全平。无平仓信息为“未平仓”；平仓数量等于开仓数量为“已平仓”；数量不一致为“数据异常”。它不适用现货船名、客户和长协必填规则，不自动计算盈亏，期货量与期货不含税利润可为空。
